# 디자인 검사

이 저장소의 화면 규칙과 검사 방법. 공통 절차(측정, Jev 판정, 실패 항목만 고치기)와 기본 규칙은 전역 스킬 `jev-design-check`를 따르고, 여기에는 이 프로젝트의 규칙과 명령만 둔다. 규칙을 바꾸면 이 문서, `scripts/check-design.mjs`의 `RULES`, `CHANGELOG.md`를 함께 고친다.

## 명령

```sh
npm run check:design                                   # 수치 기준만
~/SERVICES/docent/jev-env npm run check:design         # 관리자 기기: 수치 기준 + Jev
```

관리자 기기가 아니면 `TYPESAFE_API_KEY`를 환경변수로만 넣는다. 실패가 하나라도 있으면 종료 코드 1, Chrome 경로는 `CHROME_BIN`으로 바꾼다. CI에는 넣지 않는다(Chrome 글꼴 차이와 Jev 키 때문).

## 규칙 (15개)

기준 출처: KRDS 타이포그래피와 레이아웃, 토스 TDS, 당근 SEED, WCAG 1.4.8.

|---|---|---|
| 본문 크기 | 16px 이상 | |
| 행간 | 1.5 이상 1.7 이하 | |

| 제목과 본문 사이 | `###` 제목과 굵은 한 줄 소제목 모두 4px 이상, 문단 사이의 절반 이하 | |

| 소제목 크기 | 본문의 1.2배 이상 | |
| 한 줄 글자 수 | 한글 44자 이하 | |

화면 문구에 가운데 점과 엠 대시를 쓰지 않는 규칙은 코드 검사 대상이 아니라 리뷰에서 본다.

## 측정 표본

- 1440x900 headless Chrome, 빈 임시 HOME과 표본 Claude Code 세션 하나로 서버를 띄운다. 모델 호출은 하지 않는다(`OMP_BIN=/usr/bin/false`).
- 세션 전체 대화를 열고 실제 Markdown 렌더러(`mountMarkdown`)로 표본 답을 그린다: 결론, 문단, `###` 제목, 굵은 한 줄 소제목, 목록, 표가 든 자세히 보기, 행동 버튼, 메타 줄.
- 입력창은 한 줄, 세 줄, 바로잡기 버튼이 보이는 상태를 각각 잰다.
- 작은 창은 headless에서 열 수 없어서, 같은 스타일시트의 `.pip-card`와 `.event-title`을 본문에 그려 크기를 비교한다.

## 함정

- `:first-child { margin-top:0 }`가 `.md-lead` 규칙에 진다. `:first-child:is(*, .md-lead)`로 우선순위를 올린다.
- 입력창은 `align-items:flex-end`라서 한 줄 요소들의 높이 기준을 34px 하나로 맞춘다.
- 진행 상태 문구는 대화 안 말풍선에만 둔다. 입력창 위에 같은 문구를 다시 쓰지 않는다.
