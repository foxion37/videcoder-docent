# 0017 — 대화 중심 화면: 작업 흐름을 고르고 이어 묻기

Date: 2026-09-23
Status: Accepted. ADR 0004의 고정 4슬롯 중 "이렇게 말하면 돼요", ADR 0015의 작업 카드 안 자동 설명 표시를 대체한다.

## Context

화면이 출력 양식 중심이었다. 사건마다 설명·요청 문장·학습 상태·근거 버튼이 반복되어 사용자는 무엇을 읽어야 할지 몰랐다. "이렇게 말하면 돼요"는 용도가 모호했고, 필요한 순간인지는 에이전트가 판단할 일이 아니라는 피드백을 받았다. 또 "그럼 두 번째는?"처럼 이어 묻기가 자연스럽지 않았다. 서버는 관련 학습 기억만 전달하고 대화 흐름과 사용자가 고른 대상은 전달하지 않았다.

공개 도구 조사(Explainpaper, SciSpace, NotebookLM, Cursor Ask)에서 공통점은 사용자가 궁금한 부분을 고르고, 그 맥락에서 이어 묻고, 근거는 필요할 때 원문으로 확인하는 흐름이었다. 사용자가 방향을 승인했다.

## Decision

1. **화면은 작업 흐름과 도슨트 대화 두 영역.** 작업 흐름에는 선별된 질문·결과·계획이 짧은 제목으로 쌓인다. 항목을 누르면 그 내용이 질문 대상이 되고 설명이 대화에 한 번 펼쳐진다. 자동 설명은 미리 준비만 하고 대화에 밀어 넣지 않는다.
2. **질문 대상은 사용자가 고르고 해제한다.** 입력창 위에 짧은 제목과 해제 버튼만 둔다. 새 사건이 도착해도 대상·입력·읽던 위치를 바꾸지 않는다. 맨 아래를 보고 있을 때만 따라 내려간다.
3. **이어 묻기 맥락.** `POST /api/ask`는 선택 입력 `focus {label ≤200자, text ≤8000자}`를 받는다. 설명 호출에는 질문 대상과 같은 세션·프로필의 최근 수동 문답 6개(자동 설명 제외)를 데이터로 전달한다. 사실 근거는 여전히 현재 전사이며 과거 답변은 인용 근거가 아니다. 분류 호출에도 대상이 전달된다. 문답 레코드에 `focus`를 저장한다. 대상이 없으면 요청 서명이 바뀌지 않아 기존 requestId 재전송과 호환된다.
4. **답 형식은 결론 · 핵심 설명 · 선택적 "더 자세히:".** 설명은 질문 모양(뜻, 비교, 이유, 단계)에 맞춘다. "이렇게 말하면 돼요" 슬롯을 없앤다. 에이전트에게 보낼 문장은 사용자가 요청했을 때만 본문에 쓴다. 저장된 과거 답의 `say` 필드는 표시하지 않는다.
5. **이름과 배치.** 근거 → "원문 보기". 학습 상태 편집은 답변에서 빼서 "배운 내용 다시보기"(구 복습)로 옮긴다. 용어집은 "내 용어 사전"이고, 대화 중 "용어 뜻 찾기"는 즉석 풀이다. "설명 이어서 묻기" → "질문하기". 세 가지 설명 방식은 입력창 옆 "설명 방식" 메뉴로 묶는다. 자동 설명 켜기와 상태 표시는 Settings에만 둔다.
6. **앱이 만든 요청문은 화면에 보이지 않는다.** 대화에는 사용자가 누른 행동 이름("쉽게 설명해줘", "10초 안에 이해가능하게 설명")과 질문 대상 제목만 보인다.
7. **한국어.** 코어 프롬프트에 번역투를 줄이되 주체·조건·확실성은 바꾸지 않는다는 규칙을 둔다. 별도 윤문 모델 호출은 추가하지 않는다.

## Consequences

- 사용자는 필요한 항목만 골라 읽고, 같은 맥락에서 짧게 이어 물을 수 있다.
- 설명 호출 입력이 최근 문답만큼 늘어난다(문답당 최대 약 1,800자).
- 자동 설명은 항목에 "설명이 준비됐어요"로만 보여서, 누르지 않으면 읽히지 않는다.
- 대상 텍스트가 7,800자를 넘으면 앞뒤만 보내므로 재접속 후 자동 설명 연결이 끊길 수 있다.
- 영향 범위: `prompt/docent.md`, `app/dialogue.mjs`(신규), `app/server.mjs`, `app/learning.mjs`, `app/slots.mjs`, `app/index.html`, `tests/`, `docs/`, `README.md`
