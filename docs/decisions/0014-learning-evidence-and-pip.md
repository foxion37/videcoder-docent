# 0014 — 웹앱 전용 학습 기억, 근거 연결, PiP

Date: 2026-09-22
Status: Accepted. 사용자 승인. ADR 0004의 전체 800자·코드 금지, ADR 0010의 반복 질문 처리, ADR 0011의 원격 문답 합치기를 아래 범위에서 대체한다.

## Context

문답 저장과 용어 집계만으로는 사용자마다 무엇을 이해하지 못했는지, 어느 깊이로 알고 싶은지 알 수 없다. 같은 개념·의문을 다시 묻는 것은 이전 설명으로 해결되지 않았다는 신호다. 그러나 새로운 사건, 요청 재전송, 자동 질문은 반복 학습 실패와 구분해야 한다. 설명의 근거도 원문으로 확인할 수 있어야 한다. 사용자는 웹앱만 사용하고, 작업창 위에 Document PiP를 띄우는 방식을 승인했다. HELL 난이도와 창 투명도는 제외한다.

## Decision

### 사용자별 학습 모델

- 프로필 × 개념 × 범위로 이해 상태를 관리한다. 범위는 일반 지식, 호스트·작업 폴더로 식별한 프로젝트, 세션이다. 프로필은 로컬 개인화 선택이지 로그인/접근 제어가 아니다.
- 이해 대상은 AI 작업 흐름 / 개발 언어 / 개발 과정 / 코드, 기술 분야는 프론트엔드 / 백엔드 / 서버 / DB / 디자인 / 서비스 / 기타의 독립된 복수 선택 축이다.
- 상태는 확인 전(`unknown`), 미해결(`unresolved`), 이해함(`understood`), 복습 필요(`review`). 설명했다고 이해함으로 올리지 않는다. 수동 질문의 구체적인 의문은 미해결로 남기며, 상태와 미해결 메모를 사용자가 바꿀 수 있다. 변경 이력을 보존한다.
- 같은 개념·같은 의문·같은 사건의 재질문은 미해결로 처리하고 설명 전략을 바꾼다. 새로운 사건은 같은 개념이어도 반복으로 세지 않는다. 자동 질문은 수동 질문 횟수와 이해 상태를 바꾸지 않는다. 답을 기다리는 중 남긴 사용자 피드백도 덮어쓰지 않는다.
- EASY/NORMAL/HARD는 능력이 아닌 원하는 설명 깊이다. 이번 질문 설정 > 일치하는 분야 설정 > 프로필 기본값. 여러 분야 설정이 충돌하면 명시된 것 중 더 깊은 설정을 적용한다. 반복 여부로 자동 하향하지 않는다.

### 분류와 설명

- 실제 omp 읽기 전용 분류 호출 → 설명 호출의 두 단계. 분야·개념·기존 기억과의 관계를 먼저 판단해야 설명 전에 깊이와 관련 기억을 적용할 수 있다.
- 현재 프로필·범위의 기억을 최근순, 24,000자 후보 예산 안에서 분류기에 제공한다. 이는 전체 기록에 대한 무제한 의미 검색이 아니다. 누락 후보 수를 함께 전달하고 관련성을 모델이 판단한다. 분류 실패는 명시적으로 확인 전 상태와 경고를 반환하며 개념이나 분야를 꾸며 저장하지 않는다.
- 현재 전사가 과거 기억보다 우선한다. 이전 설명은 설명 전략과 미해결 지점의 참고 자료이며 원문 사실을 대체하지 않는다.
- EASY는 짧은 핵심과 예시, NORMAL은 작동 원리, HARD는 코드·선택 이유·예외를 다룬다. 첫 결론은 짧게 유지하고 상세 설명은 펼쳐 본다. 코어는 호스트·도구·경로 중립, 설명 전용을 유지한다.

### 저장과 재전송

- 의존성 0, Node 22 호환을 유지한다. `DOCENT_HOME/learning.json`에 프로필, 개념, 문답, 요청 완료 상태를 단일 트랜잭션으로 저장한다. 임시 파일 쓰기·fsync·rename과 프로세스 내 쓰기 직렬화를 사용한다. 같은 저장 폴더를 여러 서버 프로세스가 동시에 수정하는 구성은 지원하지 않는다.
- 답변·근거 원문은 문답 레코드 한 곳에만 저장한다. 개념의 설명 이력과 완료 요청은 recordId를 참조하고 조회할 때 복원한다. 수정 이력과 과거 설명을 삭제해서 최적화하지 않는다.
- 기존 `questions.jsonl`은 수정하지 않고 기본 프로필의 과거 기록으로만 읽는다. 원격의 동일 프로필 이름/ID는 같은 사용자라는 증거가 아니므로 원격 문답 자동 합치기는 중단한다. 원격 세션·전사·라이브 조회는 유지한다.
- requestId가 같은 동시/재전송 요청은 같은 결과를 돌려준다. 다른 질문에 같은 ID를 쓰면 409. 실행 도중 서버가 중단된 요청이나 저장된 실패는 자동으로 모델을 재호출하지 않고 명시적 새 질문을 받는다.

### 검증 가능한 근거

- 정규화한 기록마다 원본 메시지 ID, 내용 버전, 조각 식별자, 등장 순서에 기반한 소스 표시를 붙인다. 서브에이전트의 식별자도 보존한다. 전사가 늘어도 기존 위치는 유지되고, 원문이 바뀌면 이전 근거로 조용히 연결하지 않는다.
- 모델이 출력한 `근거: [ref:…]`는 실제 제공한 전사 안의 완전한 소스와 대조한 뒤에만 링크가 된다. 잘려 제공하지 않은 근거, 존재하지 않는 ID는 링크를 만들지 않는다.
- 길이·해시로 소스를 감싸 코드 안의 헤딩·참조 모양을 원문으로 취급한다. 긴 전사 축약도 소스 내부의 헤딩을 대화 경계로 오인하지 않는다.
- 웹앱 근거 패널은 원문의 해당 기록과 앞뒤 최대 두 기록을 보여 준다. 선택 기록 8,000자, 주변 기록 각각 1,600자 한도이며 잘림을 표시한다. 답변에는 근거당 최대 800자의 당시 발췌를 남긴다.
- 근거 조회는 선택 프로필이 저장한 인용인지 먼저 확인한다. 원격 오프라인·삭제·변경으로 원본이 없으면 당시 발췌를 원문과 명확히 구별해 보여 준다. 옛 무식별 전사는 내용과 등장 순서 기반이라는 제한을 표시한다.

### 웹앱과 PiP

- 사용자 표면은 웹앱만. Hermes/Telegram은 계획에서 제외한다. 기존 서브에이전트 어댑터는 코어 평가·배관용으로 유지한다.
- 지원 브라우저의 Document Picture-in-Picture만 사용한다. HTTPS 또는 localhost 보안 컨텍스트와 사용자 클릭이 필요하다. 미지원이면 사유를 표시하며 일반 팝업으로 바꿔치기하지 않는다.
- 미니 창은 본문의 프로필·세션·입력 초안·이번 질문 깊이·최신 답·진행 상태를 공유한다. 별도 모델 호출이나 SSE 연결을 만들지 않는다. 근거·복습은 본문에서 연다.
- 접기는 본문을 숨기고 창 높이를 줄인다. 크기·위치·최상단 표시의 실제 제약은 브라우저에 따른다. 부모 페이지를 닫거나 새로고침하면 PiP도 닫힌다. 자동 답변으로 초점을 빼앗지 않는다.
- 창 투명도·뒤 앱 클릭 통과·작업창 자동 추적은 제공하지 않는다.

## Consequences

- 분류를 먼저 하므로 모델 호출 비용과 대기 시간이 늘어난다. Jev 키가 없어도 개인화 분류는 동작한다.
- 저장 상태를 매번 읽고 원자적으로 다시 쓰므로 기록 규모가 커지면 측정 후 SQLite 같은 저장 방식으로 옮길 수 있다. 지금은 별도 DB 의존성·실험적 런타임 요구를 추가하지 않는다.
- 학습 기억은 모델 자체의 훈련이나 전체 기록 무제한 검색이 아니다. 사람별로 관련된 설명 맥락을 찾아 제공하는 기능이다.
- 사용자 선택 프로필은 보안 인증이 아니다. 신뢰된 로컬/사설망 전제는 유지한다.
- 코어 변경 후 설치 스크립트를 다시 실행한다. 버전 증가·배포·운영 서비스 재시작은 별도 승인 시 진행한다.
