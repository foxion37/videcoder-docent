# 0029 — 설명 요청의 중단·바로잡기·대기 질문

Date: 2026-09-25
Status: Accepted. ADR 0014 "저장과 재전송"에 중단 상태를 더한다. 같은 requestId 재전송 규칙은 유지한다.

## Context

질문을 잘못 보내도 멈추거나 고칠 방법이 없었다. 설명 중에 보낸 두 번째 질문은 조용히 버려졌다. 자동 설명 대기열은 수동 질문보다 먼저 실행됐다. 브라우저가 연결을 끊어도 서버의 모델 호출 두 개는 끝까지 돌았다.

## Decision

1. **요청은 서버의 설명 작업 하나다.** 상태는 대기 → 실행(분류·설명) → 완료·실패·중단이다. 같은 requestId와 같은 내용으로 다시 요청하면 새 작업을 만들지 않고 진행 중인 작업에 붙는다. 스트림을 요청하면(`Accept: application/x-ndjson`) 조각·상태·최종 답을 줄 단위로 보낸다. 요청하지 않으면 지금처럼 완성된 JSON을 준다.
2. **중단(Esc).** 작업을 멈추고 모델 호출을 끊는다. 문답은 남지 않는다. 요청은 `cancelled`로 기록되며, 같은 requestId로 다시 보내도 모델을 부르지 않는다. 보낸 문장은 입력창으로 돌아가 고쳐서 새로 보낼 수 있다. 연결이 끊긴 것만으로는 중단하지 않는다. 다시 붙을 수 있어야 하기 때문이다.
3. **바로잡기(⌘Enter 또는 "지금 바로잡기").** 지금 설명을 멈추고, 같은 대화 맥락(이미 보낸 전사 포함)에 보정 문장을 더해 다시 설명한다. 문답 하나로 저장하며 보정 문장을 함께 남긴다. 분류 중에 바로잡으면 설명을 시작할 때 보정을 합친다.
4. **대기 질문(Enter).** 설명 중에 Enter를 누르면 대기 질문이 된다. 차례가 오기 전에는 고치거나 지울 수 있다. 사용자의 대기 질문은 미리 설명보다 먼저 실행된다. 같은 스레드의 질문은 순서대로 실행한다.

## Consequences

- 잘못 보낸 질문을 바로 멈출 수 있고, 멈춘 만큼 모델 비용도 줄어든다.
- 서버가 진행 중 작업 목록을 갖는다. 프로세스를 재시작하면 진행 중이던 요청은 지금처럼 자동으로 다시 실행하지 않는다.
- 영향 범위: `app/jobs.mjs`(신규), `app/learning.mjs`, `app/server.mjs`, `app/index.html`, `tests/`
