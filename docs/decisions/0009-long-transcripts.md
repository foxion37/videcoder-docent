# 0009 — 긴 전사: 앞쪽은 사용자 발화만, 최근 턴은 그대로

Date: 2026-09-22
Status: Accepted

## Context

omp 세션 jsonl 은 58MB 까지 있고, 정규화하면 650KB(사용자 76턴, 에이전트 230구간)다. 평가는 60KB 전사로 했다. 도슨트는 읽기 도구로 전사를 페이지 단위로만 읽을 수 있어 수백 KB 면 끝까지 읽지 못하고 답이 앞부분에 치우친다(`docs/open-questions.md` 4번). 질문 대부분("지금 뭐", "에러", "다음")은 최근 턴에 답이 있고, "왜"만 앞쪽 사용자 요청까지 거슬러 간다.

후보: A 최근 N턴만 / B 압축 요약을 앞에 붙임(모델 호출 추가, 30초+) / C 앞쪽은 사용자 발화만 남기고 최근 N턴은 전부.

## Decision

1. **C.** `app/trim.mjs` 의 `trimTranscript(md, max)`. 전사가 120,000자를 넘으면 `## user` 헤딩 기준으로 턴을 나누고, 앞쪽 턴은 사용자 발화(500자까지)만, 최근 12턴은 그대로 둔다. 그래도 넘으면 최근 턴 수를 절반씩 줄이되 4턴 아래로는 안 내려간다. 4턴으로도 넘으면 그대로 넘긴다(도슨트가 페이지로 읽는다).
2. **줄였다는 사실은 전사 안에 `## system` 한 구간으로 적는다.** "앞 N턴은 사용자가 한 말만 남기고 줄였어요. 마지막 M턴은 그대로예요." 코어 프롬프트는 바꾸지 않는다 — 전사가 시간순 텍스트라는 가정만 지키면 된다.
3. **줄이는 곳은 `/api/ask` 뿐.** `GET /api/transcript`(기록 원문 링크)와 CLI 정규화 스크립트는 전문을 그대로 낸다. 서브에이전트 경로(`history://`)는 호스트가 페이징하므로 손대지 않는다.
4. 제공자 무관. omp·Claude Code 전사가 같은 모양(`## user` / `## assistant`)이라 헤딩만 본다.

## Consequences

- (+) "왜" 질문의 근거(사용자가 언제 무엇을 시켰나)가 앞쪽에 남는다. 최근 질문은 전문으로 답한다.
- (+) 모델 호출·비용·시간 추가 없음. 650KB → 약 100KB, 정규화 포함 0.3초.
- (−) 앞쪽 에이전트 결정 이유("에이전트가 정한 거면 그 이유를 인용")는 사라진다. 그 턴이 최근 12턴 밖이면 "기록에 없어요"로 답하게 된다. 사용자가 더 물으면 세션 원문 링크로 볼 수 있다.
- (−) 120,000자 상한은 도구 페이징 한계를 정확히 잰 값이 아니라 평가 전사(60KB)의 두 배로 잡은 값. 답이 앞부분에 치우치면 낮춘다.
