# 0002 — 범용 호스트, 코어/어댑터 분리, 첫 어댑터는 omp

Date: 2026-09-21
Status: Accepted

## Context

도슨트는 특정 에이전트 전용이 아니라 omp, Claude Code, Hermes 등 여러 호스트에 붙어야 한다(사용자 결정). 세 호스트 모두 서브에이전트·스킬을 마크다운 프롬프트 파일로 정의하지만, 프론트매터 스키마와 세션 전사 접근 방식이 다르다.

- omp: `~/.omp/agent/agents/*.md` 또는 `.omp/agents/*.md`. 전사는 `read history://<id>` 로 즉시 읽힘.
- Claude Code: `~/.claude/agents/*.md`. 서브에이전트가 부모 대화를 못 봄. 전사는 `~/.claude/projects/**/*.jsonl` 직접 파싱 필요.
- Hermes: `skills/` 트리. 코딩 세션 전사 접근 경로 없음.

## Decision

1. **코어는 호스트 중립 프롬프트 하나** — `prompt/docent.md`. 호스트 이름, 도구 이름, 파일 경로를 쓰지 않는다. "전사는 과제 지시문이 알려준 위치에서 읽는다"로만 명시한다.
2. **어댑터는 호스트별 얇은 껍데기** — `adapters/<host>/`. 프론트매터(이름·도구 제한·모델)와 전사 위치 전달 방법만 담는다. 프롬프트 본문은 코어를 그대로 붙인다(복사 금지, 설치 스크립트로 결합).
3. **첫 어댑터는 omp.** 전사 접근이 공짜라서 코어 검증에 가장 싸다. Claude Code·Hermes 어댑터는 코어가 완료 기준(@docs/scope.md)을 통과한 뒤.
4. **v0.1 스택 = 마크다운 + 설치용 셸 한 줄.** 런타임 코드 없음. 전사 파싱 코드가 필요해지는 시점(Claude Code 어댑터)에 언어를 정한다.
5. **호출은 명시적.** 사용자가 도슨트를 이름으로 부른다. 자동 감지 없음.

## Consequences

- (+) 코어 한 파일이 곧 제품. 호스트가 늘어도 프롬프트는 하나.
- (+) omp 에서 오늘 바로 스폰해 검증 가능.
- (−) 코어가 어댑터별 전사 포맷 차이를 흡수해야 함. 코어는 "전사는 시간순 사람이 읽는 텍스트"만 가정하고, 포맷 정규화는 어댑터 책임으로 둔다.
- (−) 설치 스크립트가 파일을 결합하므로 코어 수정 후 재설치 필요.
- 영향 범위: `prompt/`, `adapters/omp/`, `scripts/install-omp.sh`, `docs/architecture.md`, `docs/open-questions.md`, `AGENTS.md`, `README.md`
- ADR 0001 의 "코드 금지"는 해제. 단 런타임 코드는 여전히 없음.
