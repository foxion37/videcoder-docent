# 0015 — 설명 중심 화면과 Streamdown

Date: 2026-09-22
Status: Accepted

## Context

사용자는 도구 출력과 중간 작업 과정을 모두 읽으려는 것이 아니다. AI가 사용자에게 묻는 질문, 작업 결과, 계획안을 이해하고 싶다. 기존 화면은 전사 발췌를 먼저 보여 주어 어려운 문장과 Markdown 기호가 그대로 노출됐다. 사용자가 Streamdown 도입과 선별 이벤트 자동 설명을 명시적으로 선택했다.

## Decision

1. **사용자에게 보여 줄 사건은 질문·결과·계획이다.** 일상적인 진행 중계, 도구 오류 출력, 프로세스 종료 자체는 설명 카드가 아니다. 사용자의 결정이 필요한 막힘은 질문, 확인된 실패 보고는 결과에 포함할 수 있다. 원문은 전사에 남긴다.
2. **선별과 설명은 다르다.** Jev는 어시스턴트 발화의 의미를 선별한다. 구조화된 질문은 직접 인식한다. 판정기를 사용할 수 없으면 길이로 중요도를 추정하지 않고 구조화 질문만 보여 주며 제한을 알린다. 임의의 원문 발췌를 쉬운 설명이라고 표시하지 않는다.
3. **새 중요 사건은 쉬운 설명이 기본이다.** 선별된 새 질문·결과·계획을 기존 설명 요청 경로에서 EASY로 설명한다. 사용자가 자동 설명을 명시적으로 껐으면 유지한다. 직렬 처리·10분당 5개 상한·중복 방지·프로필 분리·세션 전환 큐 취소를 유지한다. 과거 재생은 자동으로 설명하지 않는다. 대기·한도·실패는 상태와 수동 설명 행동으로 드러낸다. 자동 설명은 사용자의 이해도 평가나 반복 질문 횟수에 반영하지 않는다.
4. **Markdown 표시 모듈은 Vercel Streamdown이다.** React 기반 렌더링과 로컬 프런트엔드 빌드를 허용한다. ADR 0005·0007의 의존성 0·빌드 없음은 이 결정으로 대체한다. 나머지 화면 전체를 새 프레임워크로 옮길 필요는 없다. 배포 패키지에 생성 자산을 포함하고 실행 시 CDN을 사용하지 않는다.
5. **기호가 아니라 구조를 표시한다.** 강조·번호 목록·표·인용·코드·콜아웃을 읽기 좋은 형태로 표현한다. 임의 HTML, 실행 가능한 링크, 추적 이미지는 허용하지 않는다. 굵은 왼쪽 장식선과 불필요한 색·배지는 넣지 않는다. 본문·복습·PiP에서 같은 렌더링 원칙을 쓴다.
6. **짧은 요지와 자세한 내용은 계층을 나눈다.** 긴 설명은 아코디언, 큰 보기 등으로 열고 원문은 별도 구분한다. 표·중첩 목록·코드 블록을 줄 단위로 쪼개 구조를 잃지 않는다.
7. **개발 용어는 문맥 안에서 풀어 본다.** 저장된 뜻풀이가 있으면 클릭해 바로 보고, 없거나 추가 문맥이 필요하면 명시적으로 설명을 요청한다. 코드·URL 내부의 단어를 무분별하게 링크로 바꾸지 않는다. 모델이 지어낸 링크를 신뢰하지 않는다.
8. **정해진 질문 대신 설명 방식 행동을 제공한다.** 더 쉽게·비유로·전체 맥락·자세히는 현재 설명 또는 선택한 사건을 대상으로 한다. 대상이 없으면 비활성화하고, 무엇을 다시 설명하는지 보여 준다. 이전 사건과 현재 사건을 혼동하지 않는다.

## Consequences

- 사용자는 작업 로그를 해독하는 대신 중요한 선택·결과·계획의 설명을 읽는다.
- 자동 설명에 모델 호출 비용과 지연이 생긴다. 상한 이후에는 수동 설명이 필요하다.
- npm 의존성·빌드·Markdown 보안 검증이 유지보수 대상이 된다. 릴리스는 빌드된 자산까지 검증한다.
- 판정기가 없으면 구조화되지 않은 결과·계획의 라이브 안내 범위가 줄어든다. 전사 자체나 수동 질문 기능은 유지한다.
