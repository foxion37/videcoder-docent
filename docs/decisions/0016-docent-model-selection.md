# 0016 — 도슨트 모델 선택은 설명량이 아니라 토큰 단가를 위한 설정

Date: 2026-09-22
Status: Accepted

## Context

사용자는 설명 길이나 토큰 수를 줄이자는 뜻이 아니라, 토큰당 비용이 낮은 모델을 선택하고 싶다고 정정했다. 학습 맥락 분류와 설명 생성은 모두 omp 호출이므로 하나만 저렴하게 바꾸면 비용 의도를 충족하지 못한다.

## Decision

1. Settings에서 학습 프로필별 도슨트 모델을 선택한다. 값이 없으면 기존 omp 기본 모델을 사용한다. 작업 중인 원래 세션의 모델과 설정은 바꾸지 않는다.
2. 한 요청을 시작할 때 선택을 고정한다. 학습 분류와 설명 생성은 같은 명시적 모델을 사용한다. 도중에 프로필 설정을 바꿔도 이미 시작한 요청은 바뀌지 않는다.
3. 선택은 omp 모델 카탈로그의 정확한 provider/selector로 검증한다. 모델 이름의 느슨한 유사 검색을 사용자 설정 계약으로 삼지 않는다. 카탈로그 등재가 해당 계정의 인증·과금·사용 가능성을 보장하지는 않는다.
4. 명시적으로 선택한 모델의 실행이 실패하면 오류를 알린다. 기본 모델이나 더 비싼 모델로 자동 전환하지 않는다. 기존 requestId의 완료 결과는 이후 설정·카탈로그 변경과 관계없이 재사용한다.
5. 입력·출력 단가는 별도로 표시한다. omp 카탈로그의 USD/백만 토큰 참고값이며 실제 계정 청구액이 아니다. 구독·프록시·계약별 과금은 별도이고, 0이라는 카탈로그 값도 무료임을 보장하지 않는다. 알 수 없는 단가는 알 수 없다고 표시한다.
6. 답변에는 요청 당시 선택한 모델을 남긴다. 이는 요청한 모델이지 호스트 내부 실행을 별도 계측한 결과는 아니다. 과거 답변을 현재 프로필 선택 모델의 답으로 바꾸어 표시하지 않는다.
7. 이 변경으로 설명 길이·깊이·토큰 제한·자동 설명 정책을 변경하지 않는다. 토큰 사용량 수집이나 청구액 계산 기능도 이번 범위에 넣지 않는다. Jev의 라이브 사건 선별은 별도 판정 경로를 유지한다.

## Consequences

- 모델별 입력·출력 단가를 비교하면서 기존 설명 기능을 유지할 수 있다.
- 카탈로그에 있어도 인증·할당량·공급자 문제로 실패할 수 있으며 사용자가 다른 모델을 직접 선택해야 한다.
- 비용 선택이 정확해지는 대신 모델 선택 저장·요청 시 카탈로그 확인과 오류 처리가 필요하다.
