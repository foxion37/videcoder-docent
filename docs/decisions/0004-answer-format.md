# 0004 — 답 형식: 4슬롯 평문, 상태 이모지

Date: 2026-09-21
Status: Accepted

## Context

첫 평가 15답은 사실은 맞았지만 모양이 흔들렸다. 결론이 3~4문장으로 늘어지고, 핵심이 "더 자세히" 불릿 안에 숨고, "이렇게 말하면 돼요" 문장에 조건("혹시 …라면")이 붙어 바로 못 보내는 경우가 있었다. 출력 구조를 고정할 필요가 있었다. 향후 Telegram(Hermes) 화면 한 장에 들어가야 한다는 제약도 있다.

## Decision

1. **4슬롯, 순서 고정, 평문.**
   - 상태 이모지 하나(✅ 끝남 / ⏳ 진행 중 / ⛔ 막힘) + 결론 정확히 1문장
   - 설명 2~4문장
   - `더 자세히:` 불릿 ≤5 (선택)
   - `이렇게 말하면 돼요:` 0~3개, `번호) 목적 — "문장"`. 문장은 조건 없이 바로 보낼 수 있어야 하고, 조건은 목적 자리에 둔다.
2. **800자 상한.** 넘치면 "더 자세히"부터 줄인다.
3. **이모지는 상태 표시 하나만** 허용. "이모지 없음" 규칙의 유일한 예외.
4. **JSON 스키마 + 호스트별 렌더러는 채택하지 않는다.** 슬롯 헤딩(`더 자세히:`, `이렇게 말하면 돼요:`)이 구분자 역할을 하므로, 나중에 버튼 등으로 렌더할 호스트가 생기면 헤딩 파서로 나눈다. ADR 0002 "런타임 코드 없음" 유지.
5. 질문 유형별로 각 슬롯에 무엇을 넣는지는 `prompt/docent.md` 의 표가 정본.

## Consequences

- (+) 첫 줄만 읽어도 "괜찮은지" 알 수 있다. 바이브코더의 실제 첫 관심사.
- (+) 어느 호스트에서도 그대로 출력 가능. 파싱 가능성은 남겨 둠.
- (−) 800자 안에 못 담는 긴 답(예: 실패 9단계 설명)은 잘린다. 사용자가 더 물으면 되므로 감수.
- (−) 상태 판단이 어려운 질문("왜", "파일")은 이모지를 생략할 수 있게 열어 둠. 일관성보다 정직성.
- 영향 범위: `prompt/docent.md`, `docs/concept.md`
